# Обработка ошибок WB Core Transport

## Единый контракт
- Основная граница — `client.APIClient.Execute`. Она возвращает `client.ClassifiedError` с `Code()`, `Delivery()`, `HTTPStatus()`, `RetryAfter()`; закрытый `classifiedError` реализует `Unwrap()`. Сообщение `Error()` содержит код и известный HTTP-статус. Статус задаётся при создании ошибки, без последующей мутации.
- `DeliveryState`: `NotDispatched` — HTTP-отправка не начиналась; `ResponseReceived` — есть ответ WB; `UnknownDelivery` — отправка началась, но ответ не получен. `httptrace.WroteRequest` служит свидетельством отправки. Нельзя выводить состояние только из текста сетевой ошибки.
- До HTTP-отправки `wb.ExecuteForCabinet`, `wb.ExecutePinnedForCabinet` и `client.ExecuteResponse` возвращают `executor_unavailable` через `client.ExecutorUnavailableError`; исходные ошибки поиска кабинета/смены поколения доступны через `errors.Is`.

## Коды и причины
- Ошибки подготовки запроса и конфигурации лимитера: `invalid_request`; некорректная цель JSON: `invalid_result_target`. Очередь лимитера заполнена: `limiter_queue_full`; отмена контекста: `context_canceled`; истечение срока: `context_deadline_exceeded`. Эти случаи имеют `NotDispatched` и не маскируются под HTTP 429.
- Только ответ WB с HTTP 429 получает `rate_limited`. Прочие неожиданные HTTP-статусы получают `unexpected_status` и сохраняют статус/`RetryAfter`; ошибки чтения или разбора ответа — `invalid_response` либо `empty_response`.
- Сетевые ошибки получают `transport_error`. Приватная оболочка `safeTransportError` показывает безопасный текст без URL/параметров запроса, но `Unwrap()` сохраняет исходную причину для `errors.Is`/`errors.As`. Ошибка прерванного повтора получает `retry_interrupted`; `errors.Join` сохраняет предыдущую ошибку попытки и причину прерывания.
- Используются ранний возврат, полезный контекст через `fmt.Errorf("...: %w", err)`, `errors.Is` для sentinel-ошибок и `errors.As` для `ClassifiedError`/`net.Error`. Не определять категорию по сравнению текста `Error()`.

## Ответ WB и повтор
- Тело JSON читается и закрывается с лимитом операции. Для неуспешного HTTP `response.ErrorSummary` извлекает только `code` (строку или число), `title`, `errorText`, `requestId`; каждое поле ограничено 160 рунами и очищается от управляющих/пробельных символов. Сырое тело в лог не пишется; ошибочные/неожиданные типы полей игнорируются.
- Автоматический повтор допускается только для операции чтения с `RetryModeReadSafe` (не по HTTP-методу), максимум три попытки. Повторяемые HTTP-статусы: 429, 500, 502, 503, 504. Сетевые повторы: `io.EOF`, `io.ErrUnexpectedEOF`, тайм-аут `net.Error`; явная отмена контекста исключена. Мутации не повторяются автоматически: при неопределённой доставке решение остаётся за бизнес-реконсиляцией.
- Задержка чтения начинается с 500 мс, растёт экспоненциально и учитывает больший `Retry-After`; отмена прерывает ожидание. `flowcontrol.Observe` сообщает о плохих rate-limit headers; даже при их ошибочности локальный cooldown для HTTP 429 применяется.

## Логи и границы модулей
- Core пишет одну структурированную Zap-запись на логический запрос: операция, код, HTTP-статус, состояние доставки, попытки, время ожидания лимитера, размер и длительность. Причина первой ошибки наблюдения rate-limit headers выводится отдельно от счётчика; она поднимает уровень до Warn даже при успешном HTTP. Ошибка с кодом `context_canceled` без такой ошибки — Debug; другие коды логируются по обычному правилу Warn. Слои выше добавляют контекст, но не дублируют лог того же запроса.
- `wbcabinet` трактует /ping 401/403 как отклонение токена, 429 как ограничение WB, 5xx/сеть/некорректный успешный ping как временный сбой. `service.Add` сохраняет эту категорию; Telegram показывает отдельные сообщения, а восстановление повторяет временные ошибки. Сентинел и причина сохраняются совместно через `%w`.
- Классификаторы публикации используют `Delivery` и не меняют прежние сохраняемые `WB_CALL_NOT_DISPATCHED`/`WB_MEDIA_CALL_NOT_DISPATCHED` для `executor_unavailable` с `NotDispatched`. При изменении смысла сохраняемых кодов требуется версия классификатора.
- HTTP 200 с `Content.ResponseMeta.Error` остаётся бизнес-ошибкой конкретной функции, включая ошибки отдельных карточек. Универсальный HTTP executor не превращает любой такой envelope в транспортную ошибку.

Связанные сведения: `mem:core/wb_client`, `mem:features/modules`, `mem:features/cardpublication`.
